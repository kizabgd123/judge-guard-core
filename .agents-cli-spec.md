# Agent Spec: JudgeGuard Reflexive GitHub CI/CD Workflow & Autonomous Healer

## Overview
This agent system automates a transparent, reflexive, and self-healing CI/CD workflow on GitHub for **JudgeGuard** and the Trinity Protocol ecosystem. It guarantees compliance with the Master Orchestration Constitution (Laws 1–5), validates every pull request/push, and in the event of pre-action verification failure or test regressions, triggers an automated Reflex Healer agent. The Reflex Healer inspects errors, emits a structured `guard_alert.json`, synthesizes resolutions from Trinity Protocol Constitutional knowledge (sourced from NotebookLM), executes bounded self-healing (e.g. restoring WORK_LOG parity, renewing stale timestamps, correcting state drifts), and reports transparently to GitHub Step Summaries.

## Language
`python`

## Architecture & Roles
- **GitHub Actions Workflow (`.github/workflows/judge_guard_ci.yml`)**: Entrypoint for CI validation running under `uv`.
- **JudgeCoordinator**: High-level orchestrator executing the layered verification sequence.
- **JudgeVerifier**: Enforces Layer 00 (Security Hard Rules), Layer 0 (WORK_LOG Parity & Freshness), Layer 1 (Tool Discipline), and executes pytest test suites. Issues HMAC-SHA256 Execution Tickets.
- **ReflexHealer**: Self-healing reflexive sub-agent that intercepts verification blocks (Exit 1), generates structured `guard_alert.json` payloads with `actionable_fallback` directives, performs at most 1 bounded recovery cycle, and logs execution diagnostics.

## Example Use Cases
1. **Standard Compliant PR**:
   - Input: Developer or agent opens PR with updated code, active `WORK_LOG.md` entry, and passing tests.
   - Flow: GitHub Actions invokes `judge_guard.py` -> Layer 00 & Layer 0 PASS -> `pytest` passes -> Green checkmark + summary.
2. **Stale WORK_LOG or Parity Disparity (Reflexive Recovery)**:
   - Input: PR has `WORK_LOG.md` older than 120s or minor disparity in starting action.
   - Flow: `judge_guard.py` exits 1 -> `ReflexHealer` intercepts -> Emits `guard_alert.json` -> Queries Trinity Constitution -> Executes `heal_work_log_parity` -> Re-runs verification -> PASS -> Logs self-healing actions into Step Summary.
3. **Hard Security Violation (Constitutional HALT)**:
   - Input: PR contains dangerous commands (`sudo`, `rm -rf /`) or mock attempts.
   - Flow: Layer 00 triggers immediate block -> `ReflexHealer` detects non-recoverable violation -> Halts immediately (Exit 43) -> Emits full diagnostic alert without bypassing or faking verifications.

## Tools Required
- **JudgeGuard Gate (`judge_guard.py`)**: Local gate checking hard security, WORK_LOG parity, and cryptographic ticket generation.
- **Reflex Healer CLI (`scripts/judge_reflex_healer.py`)**: Executes failure triage, NotebookLM / local Trinity rules lookup, and bounded remediation.
- **Trinity Constitution Rules Store (`docs/trinity_constitution_rules.json`)**: Deterministic local knowledge base fallback containing Sections 46, 48, and 49 of the Trinity Protocol Constitution (satisfying Law 1: Zero-Simulation).
- **GitHub Step Summary**: Markdown emitter for agent visibility.

## Constraints & Safety Rules
- **Law 1 (Zero-Simulation & Zero-Mock Policy)**: No mocking of security gates, auth tokens, or system commands. Genuine local evaluation fallback only.
- **Law 2 (Mandatory Pre-Action Verification Gate)**: Every critical action must be gated through `judge_guard.py`.
- **Law 3 (Work Log Traceability)**: Strict lifecycle: `🟡 Starting` -> `python3 judge_guard.py "Start ..."` -> Action -> `✅ Completed` -> `python3 judge_guard.py "Verify ... Complete"`.
- **Law 4 (Code Cleanliness & Quality)**: All code must pass `pytest` and syntax checks prior to merge.
- **Law 5 (Anti-Circumvention & Execution Tickets)**: Single-use HMAC-SHA256 execution tickets. Maximum 1 reflexive auto-heal attempt; if unresolved, agent must HALT immediately without loop evasion.

## Success Criteria
- GitHub Actions CI workflow file `.github/workflows/judge_guard_ci.yml` is present, valid, and lint-clean.
- `scripts/judge_reflex_healer.py` passes all unit tests in `tests/test_judge_reflex_healer.py`.
- Auto-healing reflex successfully resolves stale/parity drift in simulated CI failure scenarios.
- All existing tests in `tests/` pass with zero regressions.
